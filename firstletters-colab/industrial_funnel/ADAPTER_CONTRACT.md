# Proposed producer / worker contract v1 (review blocking interface)

The RFC control-plane verifies artifact bytes, lineage, calibration key and resource grants. This document specifies the additional semantic validator and typed manifests the actual Claude/Gemini/Codex adapters must implement together. No field is an anatomical proof merely because it is present. Missing required fields block admission, never become a negative result. All chart-level artifacts/IDs are private.

## Immutable identity

Use canonical UTF-8 JSON, sorted keys, compact separators, finite numeric values, explicit schema version and units. SHA256 of canonical object; arrays retain binary hash, dtype, shape, endianness, order. Source snapshot includes official catalog and date, volume ID, voxel size and level, codec, chunk keys and content hashes, frame transform and its uncertainty, source access rights. Do not publish private hashes that could identify a candidate. Use original physical-face/vertex lineage, local sheet hypothesis ID, chart domain and core/halo polygons in private registry. Record orientation and local metric, not merely a filename. Same XY location on another winding is NOT duplicate.

The actual calibration key is the hash of the full inference configuration and calibration stratum (listed below). Model or wrapper, preprocessing, acquisition domain, flattening convention, resolution, precision, stride, depth sampling, orientation or TTA changes create a new key. A changed seed, parent, support, geometry, chart or frame creates a new job. A repaired result does not overwrite history. Dependencies refer to exact completed receipts and byte-verified artifacts. A new calibration event has its own identity/time, not a silent renewal.

## Native stage manifest fields (private)

| Family | Required evidence |
| --- | --- |
| registration | official eligibility snapshot; public/private source category; physical scroll; scan ID; version, frame, transform matrix with axes/units/uncertainty and independent registration evidence |
| chart geometry | original triangles and UV map with stable IDs; full-support validity and topology; reference/anchor evidence and identity uncertainty; recto/verso hypotheses; deformation and area distribution; folded/crossed/ambiguous regions; overlap candidates and proven equivalence links |
| sampling | native xyz convention and pixel-center transform; mesh/grid spacing, normal sign, actual signed depths in physical units, sample locations and trilinear footprints; input support mask per depth plus full-stack support, distinguish unacquired/stored-zero/tissue |
| calibration | full recipe fingerprint and calibration stratum, frozen protocol/positive and matched null cases, exposure/holdout, gates and all measured outcomes, validity interval, independent reviewer if needed; source/control evidence hashes |
| inference | model family and source revision, checkpoint SHA256, software/container and dependency hashes; CT normalization/precision, patch size, stride, halo, crop/context, padding, blend and order; actual model input slice order for both directions; all shifts/scales separately, no silent fused-only product |
| map output | native float array(s), each with shape/axes, physical map-to-original transform, support and uncertainty masks, no implicit resampling or stretching; verified finite values on supported pixels; invalid pixels separate, not probability zero |
| ranking | exact source map hash, physical core+halo units, ranking recipe, stage/stratum, ordinal score(s), reason codes, duplicate overlap evidence; retain all tiles, including zero-score, uncertain, low rank and unavailable |
| allocation | frozen population and ranking version, resource class/cost vector, lane, selection method, inclusion probability for probability survey, observed cost, quota status; actual private lease/grant; no forced probability interpretation of rank |
| deep / review | original native maps for all families/orders with context; cross-turn fixed-landmark and adjacent-sheet nulls; independent reviewer IDs private; blinded source-known targets for calibration only; per-unit scoped status and reason; unresolved vs reviewed explicitly |
| accounting | actual CPU/GPU/human milliseconds, I/O bytes, peak memory, hardware/precision/thermal telemetry, exit state and retries; source support and cost denominators; original physical footprint union only with verified equivalence |

Mandatory adapter validations before COMPLETE: matching source frame and hashes at entry/exit; correct array type, shape and paired map/mask alignment; finite supported scores and coordinate domain; no padded output counted as observed area; correct native depth order and matched-control key; no loss of expected accounting units; reported acquisition/compute failures explicit; resource metering and stopped-worker evidence. Raw maps preserved privately. A missing order/family or partial tile may be retained as a FAILED receipt with evidence, but cannot satisfy a full paired recipe. Distinct recipes are not interchangeable; multi-family review must name all required parents and each support intersection. The current reference queue models a linear per-recipe stage chain; joins, tile splitting and registered frame transforms require additional validators.

## Reference queue contract

Job spec: `scroll, unit, frame, stage, recipe, inputs, deps, calibration` (hashes and private IDs). Stage chain REGISTER → GEOMETRY → COARSE → RANK → DEEP → REVIEW. COARSE and DEEP each require their own matching successful CONTROL parent (same calibration key). CONTROL has no predecessor in this small reference; its real evidence sources still appear in inputs. Parent outputs must be included in child input hashes. Resource grant and lane separate from immutable job identity; contradictory duplicate scheduling policy rejected. Schema-version migration is explicit.

Completion receipt: `job, outcome, worker_stopped, actual, outputs`; outcome COMPLETE or FAILED; failed requires enumerated failure kind. CONTROL adds `calibration, control_pass, valid_until` (UTC epoch seconds). Inference requires `orders=["asc","desc"]` and five roles `asc_map,desc_map,asc_support,desc_support,metadata`, all verified CAS SHA256s. These are placeholders for actual producer-format validation (one configured inference family/recipe per job). REVIEW adds `review_status` restricted to REVIEWED_NO_QUALIFYING_READING, INCONCLUSIVE, PRIVATE_REVIEW_REQUIRED. No automated claim. Receipts are scoped to completed work under that configuration, not permanent search termination. Failed calibration, stale control, missing support, corrupt artifacts and budget blocks must appear in the aggregate bottleneck report. Actual hardware stop and attested resource usage need worker-side enforcement, not just booleans.

## Scientific gate registry (production extension)

Every gate stores frozen protocol hash, configuration key, stratum, minimum independent positive/null populations, required controls, success criteria and expiration, immutable receipts, failed/nonassessable cases and review status. Version a revocation event when source/recipe/independent control invalidated; quarantine all descendant evidence (retain cost/receipts) and reopen corresponding queue. Reference supports expiry and blocking at inference; live revocation with downstream invalidation is not implemented. No claim of universal threshold validity. A calibration path check on an exposed winner cannot certify sensitivity to previously unseen script or ink. Negative screening result is a scoped observation; prioritize differently when new evidence arrives.

## Private/public separation

Private coordinator and CAS hosted on owner-approved hardware, authentication/authorization per worker, encrypted transport/storage and backup, least privilege, no secrets in job payloads or stdout. Public CI uses only synthetic/public known-positive fixtures. Public report allowlist: scroll-level aggregate counts, resource sums, status/uncertainty bins and area bounds with documented denominator. Inspect for disclosure before publication; not automatic. No private chart IDs, positions, crops, per-candidate timestamps, raw maps, credentials, storage URLs or identifying hashes. Candidate wording follows collab/README.md. No external submission or merge without owner approval.
