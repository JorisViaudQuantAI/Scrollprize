# A03 / Adaptive 075 — self-review: file-chain admission and evidence-bound audits

Frozen 2026-11-24, based on exact A02 head 9e66591b309eeb41561c173eb52932527370977b, before new test results. Independent correction, not duplicating Gemini G1/G3/G4 or Claude S0/S1. Review of our own 073/074 code identifies two critical gaps:

1. FileReceipts validates a single result's bytes but does not establish actual parents, calibration or independently authorized grants. Its resume flag eligible_for_standard_chain could be misread as approval. A missing/failed/revoked parent can therefore coexist with a locally "complete" child. A receipt can declare a larger grant than the owner intended. A stale or experimental result must not enter normal descendants.
2. order_audit.audit_summary is an arithmetic helper accepting outcome strings. Even all-zero labels can produce a bound with no actual paired maps, missing attempted charts or independently bound review evidence. Its internal budget_feasible=True is not measured budget evidence. Do not use that helper alone for an operational audit.

## File-first correction
New offline batch verifier, not another coordinator service. Immutable versioned batch manifest: exact job specs, full authorized ancestor graph, bounded positive integer grants for each authorized attempt, epoch name, dated eligibility snapshot (provided by operator), total resource vector, fixed operator-provided producer/reviewer labels only in private adjudication. Sum worst-case grants across ALL authorized attempts <= cap; no reuse of unspent grants, no silent budget reset. Validate pinned manifest hash against independently trusted expected hash supplied by operator, not a hash read from the same object. Exact parent stage/scroll/frame/unit and matching control key, experimental coarse cannot parent standard jobs. Require all parent specs present; no cyclic graph. For already materialized content-addressed inputs only, immutable spec includes actual input hashes; later stages with new unknown hashes require explicit new operator-approved batch with carried-over cost, not automatic batch creation. The verifier's budget is batch-local; no cross-batch/global spend claim. All source/output bytes checked through existing FileReceipts. Match actual receipt grant to authorized grant for its attempt; unknown attempt, noncontiguous attempts, conflicting completed attempts, overrun, corrupt/missing bytes or unauthorized lineage block reuse. Parent output hashes must appear in child inputs. A failed or partial result never unlocks a successor. Report spent, reserved worst case and missing attempts; actual resource overrun blocks all new work. Revocation list supplied by trusted operator, conservative current expiry/failed control blocks downstream new work even if old receipt preserved; this can overblock historical evidence intentionally. No automatic retries of in-flight tasks: report READY_FOR_OPERATOR, not dispatch. Single operator; no proof of liveness, actual time, identity/authentication or filesystem security on Windows. Old FileReceipts.resume becomes local availability only; standard-chain flag always false without verifier. Old byte-level publish remains possible for partial/history but not authority.
